02Participate

How to participate in the challenge.

What a participant does: take a case from one of the three tracks, run a model and its harness on it end to end, have the deliverable checked against references the agent never sees, and turn what happened into something others can inspect and reuse.

  1. 01

    Choose a case

    The participant takes a case from a track and opens it: the task goal, the evidence available at the decision point and its constraints. Every entry in a track works from the same materials and is scored the same way.

  2. 02

    Configure Model + Harness

    They pick a model and the harness that runs it. The model reasons and decides; the harness supplies the tools, the workflow and the run settings, so the same model can behave differently in a different harness.

  3. 03

    Execute and record

    The agent reads the materials, plans, calls tools and writes files until it delivers end to end. Every step goes into the trajectory, so the whole run can be traced afterwards.

  4. 04

    Verify and diagnose

    The deliverable goes to an independent check against reference results and rubrics the agent never saw during the run. A result can be a pass, a partial pass or a failure, and the trajectory shows where it went wrong.

  5. 05

    Contribute

    What the run yields can be contributed in three forms: a Metacase, the structured record of the case; the Model & Harness, packaged so the run can be repeated; or a Failure Case, a reproducible failure with its diagnosis (a low score alone is not one). Contribute one or more, separately from the choice of track.

03Evaluation

From task to score.

Every run passes through three layers: the task and its data, the agent's workspace, and an evaluation the agent never sees. Hover a layer to trace it, or drag the model to turn it.

  1. L1

    Tasks and data

    Each task sets a goal, the evidence available at the decision point and its constraints. Some ask for an empirical result from a research specification, others for business deliverables from multi-file records.

    • Replication
    • Deliverables
    • Data files
  2. L2

    Agent workspace

    A model works inside a harness that supplies context, tools and feedback, and runs its code in a sandbox.

    • Model
    • Harness
    • Sandbox
  3. L3

    Independent evaluation

    Submissions are checked against withheld reference values or a task rubric before results are compared.

    • Withheld references
    • Rubric
    • Diagnosis
