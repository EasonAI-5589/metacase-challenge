econ-0157 · one recorded pilot run

A Metacase in economics

From 2013, central inspection teams entered China's government departments in five waves. After an inspection, did competition for a department's civil-service posts change? Lai and Li (The Journal of Law and Economics, 2024) answer with data on 717 recruiting departments over 2012–2017. The task is to reproduce one of their results as three numbers: how large the effect of inspection on the applicant-to-hire ratio is (the coefficient), how uncertain that estimate is (the standard error), and whether it is significant (the p-value: the chance of a difference this large if inspection had no effect at all).

The first difficulty is that the result cannot simply be run. The task takes only the data from the authors' public replication package; it names the Stata command the paper used and the authors' script, but supplies neither, and the container has no Stata. Behind that command stand three Stata programs written by others, one of them more than four thousand lines long. The agent has to read the source and rebuild the same algorithm in Python: cohort weights, the parts of the variance, which observations are dropped, the degrees-of-freedom correction. If any of them departs from the original, the result may fall outside the 1% tolerance.

The second difficulty is that the specification is incomplete, so a correct computation can still report the wrong result. The task says only that covariates are “row-specific … per table column”, without saying which column; covariates are the variables a regression uses to control for other factors. The authors' public script, checked after the run, estimates the effect more than once: −66.33 without covariates and −69.35 with five, a gap of 4.6%. The reference is the first; reporting the second scores 0. The container has network access; the agent searched public sources without finding that script, and obtained only the public source code of the estimation command itself: a general-purpose program with none of this study's settings in it.

01Context & evidence

Scoping the data and the estimand, and marking what the task leaves unspecified.

The agent has one data file and one paragraph of instructions, and no original script. Before estimating anything, it establishes which estimate the data support, which settings are stated and which are still open.

  1. Data3,246 department-year observations on 717 departments over the six years 2012–2017, with 30 labelled variables. The data come from the authors' public replication package and are supplied by the task.
  2. VariablesThe outcome comp is the applicant-to-hire ratio (labelled AHR), a measure of competition for each post; the treatment inspectmain equals 1 once a leading department has been inspected. Three further variables mark each department's wave and whether it was never inspected.
  3. Treatment and sampleOf the 717 departments, 119 are leading departments; 87 of them were inspected between 2013 and 2017, in five cohorts, and they account for 180 department-year observations after inspection. The other departments were never inspected and form the control group, the baseline against which the effect of inspection is measured.
  4. Four settingsThe task states department and year fixed effects, cohorts by first inspection year, never-inspected departments as controls, and clustering by department. Fixed effects remove each department's and each year's own average level; clustering by department allows one department's errors to be correlated across years.
  5. Open items and constraintsThree numbers are due, the coefficient, its standard error and its p-value, with a standalone Python script that reproduces them. The authors' script is not supplied, there is no Stata, and the limit is 30 minutes; which column's covariates to use, the task does not say.

02Prior practice & strategy

Looking for the authors' script, then falling back on the estimator's source.

Prior practice exists at two levels: the authors' own script, and the estimation command the task names. The first was never found; the second is a public, general-purpose program. Every choice the agent makes is kept in its step record.

  1. Rules and practiceThe command the task names, eventstudyinteract, implements the Sun–Abraham interaction-weighted estimator: each cohort's effect is estimated separately, then weighted by the cohort's share of treated observations. With inspections arriving in waves, an ordinary two-way fixed-effects regression would use departments already inspected as controls, which is what this estimator avoids.
  2. Looking for the scriptThe script is not in the container. The agent searches GitHub, Google, Bing, Harvard Dataverse, DataCite and Crossref; most requests are refused or return unrelated results. It finds two replication packages, which belong to other studies, checks their file lists, finds the script in neither and explicitly declines to use them.
  3. Back to the sourceAt 24 seconds it takes the source of eventstudyinteract from its author's GitHub repository, and later the source of reghdfe and avar, on which it depends. All three are general-purpose programs and contain nothing specific to this study.
  4. Choice of specificationThe four settings the task states include no covariates, yet it also mentions covariates “per table column”. The agent estimates without covariates and gets −66.33; it tries other sets of covariates, finds that the estimates differ, and does not pick a set without support.
  5. A note left behindThe header of the delivered script and a separate note both state that this is the baseline without covariates and that which covariates each column of the script uses could not be verified.

03Actions & execution

Rebuilding the estimator from Stata source, then checking it another way.

gpt-6-astra runs in the Terminus-2 harness for about eight minutes: 40 model requests and 52 tool calls, all logged.

  1. Source readingFrom the source of eventstudyinteract it takes two points: the combined effect is the five cohort effects weighted by share (the cohorts hold 14, 8, 65, 79 and 14 treated observations), and its variance adds a term for estimating the shares to the clustered variance of the regression.
  2. Sample definitionSeventy-six departments are observed only once, and one of those observations is treated. reghdfe drops such singletons by default, so the regression uses 3,170 observations on 641 departments. The agent also reads a detail: the shares must be computed before the singletons are dropped, because the command computes shares first and calls the regression afterwards.
  3. Degrees of freedomAgainst the source of reghdfe it confirms the small-sample correction for clustered standard errors: department fixed effects are nested within clusters and not counted again; the six year effects count as five parameters.
  4. Independent checkOnce the estimator is written, it reruns the regression with explicit department and year dummies; the five cohort coefficients agree with the first result to numerical precision.
  5. FailureOne outside lookup does not return and holds the terminal, so the commands queued behind it, which write the files, never run. The agent interrupts the lookup, confirms that neither deliverable exists, then writes and runs them again.

04Outcomes & verification

Out-of-loop verification: a grader compares three numbers.

Harbor adds the grader and the reference to the container only after the agent stops. The grader calls no model; it reads the result file and compares it with the reference.

  1. Verified figuresA coefficient of −66.3269 and a standard error of 25.0531. Compared at the full precision of the result file, the coefficient matches the reference to 11 decimal places and the standard error to nine.
  2. Basis of the p-valueThe agent uses a t distribution with 640 degrees of freedom (641 departments less one) and reports 0.00831; the reference is 0.00811, which agrees with the normal distribution. The gap of 0.0002 lies within the tolerance of 0.01.
  3. Decision ruleAll three numbers must pass: a relative error (the difference as a share of the reference) of at most 1% in the coefficient and in the standard error, and an absolute error of at most 0.01 in the p-value. Passing all three scores 1; anything else scores 0, with no partial credit.
  4. The weight of a specificationAfter the run, the authors' public script (which the agent never obtained) was consulted, and the five covariates of its column 2 were put into the agent's delivered program on the same data: −69.35 with a standard error of 22.68. The coefficient is 4.6% off the reference and the standard error 9.5%; under the same rule that scores 0.

05Reflection & reuse

Reviewing the choice of specification, and the limits of a replication.

The record breaks one number into the settings it depends on, so a later attempt can check each of them rather than compare results.

  1. What heldThe estimator, fixed effects, clustering and treatment of singletons follow the public source, and the control cohort follows the task; the result is confirmed by a second method. No covariate was added without support, and what could not be verified is stated in the deliverable.
  2. The four settings in the task
    What they show
    Fixed effects, cohort variable, control cohort and clustering are stated; covariates get one phrase, “per table column”.
    Why it matters
    Different covariates give different numbers under the same estimator, 4.6% apart for the two specifications here; choosing a set without support would be deciding for the researcher.
    This run
    Reported without covariates, and stated as unverified.
  3. Variable labels in the data
    What they show
    Three variables mark each department's wave and whether it was never inspected.
    Why it matters
    When treatment arrives in waves, units not yet treated will be treated later and cannot serve as controls throughout; with the wrong controls, differences in timing between cohorts are read as treatment effects.
    This run
    Never-inspected departments used as the control cohort.
  4. Source of eventstudyinteract
    What it shows
    The variance of the combined effect has two terms, the clustered variance of the cohort effects and the variance of the estimated shares.
    Why it matters
    The first term alone gives a standard error of 24.89 rather than 25.05: the variance is understated and the confidence interval too narrow.
    This run
    Both terms included.
  5. Default setting of reghdfe
    What it shows
    The 76 departments observed once are dropped from the regression sample by default; the shares are computed before that.
    Why it matters
    Dropping them sets the sample (3,246 or 3,170), the clusters (717 or 641) and the degrees-of-freedom correction; in the wrong order, the weights change too.
    This run
    Shares first, then dropped as in the source.
  6. Basis of the p-value
    What it shows
    The agent uses a t distribution with 640 degrees of freedom; the reference agrees with the normal distribution.
    Why it matters
    For the same t statistic of −2.647, the two bases differ by 0.0002. A p-value depends on the assumed distribution and its degrees of freedom, so a report should state its basis.
    This run
    The script states its basis; the gap is within tolerance.
  7. What failedThe basis of the p-value differs from the reference and passes only on tolerance. The agent never found the authors' script: the baseline it reports is the one the task's four stated settings point to, and was not checked against that script. The estimate was confirmed by 185 seconds, after which nearly five more minutes went on searching, and one stalled lookup almost left the deliverables unwritten.
  8. Conditions and signatureApplies where public code defines the estimator and the task does not state the full specification. Signature: open specification, source comparison, numerical replication, stating what was not verified.

Conditions and signature

What carries beyond this case, and where the evidence stops
DimensionWhat this case showsLimits of the evidence
Real-world depthThe question comes from a published paper: treatment in five cohorts, never-treated units as controls, clustering by department. A research assistant often faces just this: data and one sentence about the method, with neither the original code nor the original software at hand. Reproducing it takes more than a regression command: cohort weights, a two-part variance, dropped singletons and the degrees-of-freedom correction.The data come from the authors' public replication package and are supplied by the task; the agent never learned which paper it was. The task reproduces one coefficient with its standard error and p-value; the paper's event-study figures, mechanisms and robustness checks are outside it.
GeneralisabilityThe same task package, container and grader apply to any Model + Harness pair. Other tasks in the econometric replication subtrack use the same comparison of coefficient, standard error and p-value.This page shows one run. Whether the same pair gives a stable result on repeated runs has not been tested.
Path to practiceThe deliverables are what a research assistant hands over: the numbers and a script that reproduces them. Reading the source before writing, reconciling the sample and each correction, confirming by a second method and stating what was not verified can become a checklist for replication work.A full score shows that these three numbers were reproduced, not that the script is correct for other data or specifications. The basis of the p-value still differs from the reference.
Research relevanceWith the same data and the same estimator, adding five covariates or not moves the coefficient by 4.6%, enough to push a result outside the tolerance. The agent did not know which one the reference uses: it reported the baseline the task states, and marked the uncertainty. The step record makes such a choice locatable and reviewable, and the choice of specification is what a script's self-check cannot catch. Our ModularRSI study raised strict replication from 64% to 67% on tasks of this kind.The task does not name the target column, a gap in the task text; choosing the right one owes something to the task's wording. The container has network access: the agent obtained the estimator's public source and not the authors' script, but with network access that script is not out of reach. This run did not use ModularRSI.

Grader detail: relative error 0.00% in the coefficient and in the standard error; absolute error 0.0002 in the p-value.

External addresses are counted by the URLs appearing in commands: the GitHub repositories of the estimation command and the programs it depends on, and the search interfaces of GitHub code search, Google, Bing, DuckDuckGo, Harvard Dataverse, DataCite and Crossref. Neither the author's page nor the journal's appears in the record.

The note was written to the output folder but is not one of the two deliverables the task collects, so its text survives only in the run record; the header of the delivered script carries the same statement.
