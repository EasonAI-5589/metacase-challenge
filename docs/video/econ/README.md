# econ-0157 回放视频：gpt-6-astra × Terminus-2（econ v1）

这是经济学 Metacase 页用的回放视频。它展示 econ-0157 的一次运行：gpt-6-astra 在 Terminus-2 2.0.0 里复现一篇已发表论文的一个估计值，评分脚本给出 1.000。画面里只有这一次运行，不出现其他模型或其他运行。

几个叫法：

- **引擎**：财务、HR 回放视频共用的离线渲染程序（Python + skia-python），在 `engine/` 下。
- **分镜**：`story/econ.py`，每个镜头一句旁白，旁白里的 `{标记}` 是画面动作的时间点。本片专用的画面在 `story/econ_scenes.py`。
- **运行数据**：`data/econ.json` 和 `data/econ.requests.jsonl`，画面上的请求数、工具调用、时间、token 都从这里读。

## 2 视频按什么顺序讲

措辞跟网页文案（`metacase-economics.html`，即 `网页文案-经济与社科.md` 第 6 节）对齐。

1. **题目**：论文、三个数（系数、标准误、p 值）和一份能复现它们的脚本。
2. **第一个难点，结果不能直接跑出来**：题目点名了 Stata 命令和作者的脚本，两样都没给，容器里没有 Stata。命令背后是别人写的三个 Stata 程序，其中一个超过四千行；智能体要读源码，在 Python 里重写同一套算法，四项约定（队列权重、方差的组成、剔除哪些观测、自由度修正）任何一项不一致，结果就可能超出 1% 容差。
3. **第二个难点，设定不完整**：作者的脚本把效应估了两遍，不加协变量是 −66.33，加五个是 −69.35，题目没说要哪一列，报错一列得 0 分。
4. **运行过程**：取估计命令的公开源码、读算法、处理只出现一次的部门、读回归程序的修正、搜作者脚本未果、跑出 −66.33 和 25.05、试其他协变量组合后保留基准、用显式虚拟变量再验一遍、一次查询卡住终端后中断并重写文件、在脚本头部写明没能核实的事项。
5. **检查与结果**：评分脚本逐数比对；p 值差 0.0002 的原因；事后把第 2 列的五个协变量放进智能体自己的程序得到 −69.35，同一规则下得 0 分；评分 1.000，并说明这是一次试跑的评分，不是准确率，也不是排名；最后一镜列出这份记录的边界。

## 3 每类数字从哪来

- **运行记录**：请求数 40、工具调用 52（39 条命令、10 次等待、1 次中断、2 次完成标记）、各步时间、退出码、token、画面上引用的每条命令和终端输出、智能体的三句原话、交付脚本头部的说明、两份交付物的大小。运行数据由 `tools/build_econ_data.py` 从该次运行的回放记录生成。
- **评分回执**（`verifier/reward-details.json`）：参考值、提交值、误差、评分。
- **已确认的网页文案**：两个难点的说法；作者脚本两列的数值（−66.33、−69.35，相差 4.6%）；「三个 Stata 程序，其中一个超过四千行」；评分用时 0.2 秒；事后重算的第 2 列（−69.35，标准误 22.68，系数差 4.6%、标准误差 9.5%）。
- **编辑加工**（`provenance.json` 里都写明）：
  - 左栏「SETTINGS TO MATCH」是按记录整理的八项设定，在记录显示该项落定的那一秒打勾。Terminus-2 不维护计划，智能体也没有写计划。「Column」一项始终不打勾。
  - 工具调用按「这一次调用做了什么」上色（命令、等待、中断、完成标记），依据是记录里的按键内容。
  - AGENT 一章按运行时钟排列。搜索作者脚本的动作在第 33.7 秒到第 103 秒之间与其他步骤交替进行，视频把它放在一个镜头里，时钟标在第 80.1 到 104.3 秒。

## 4 关于联网，以及一处与网页文案不同的地方

- 视频在第 9 个镜头说明容器可以联网，并在第 9、13、27 个镜头说明智能体拿到的是估计命令的公开源码，不是作者的脚本。
- 记录里实际取到的源码是两个文件：`eventstudyinteract.ado`（6,497 字节，第 23.7 秒）和 `reghdfe.mata`（第 73.0 秒）。
- **`avar.ado` 没有取到**：第 149.5 秒那条命令保存下来的文件只有 14 字节，是「找不到」的返回内容。所以视频只展示这两个文件，没有照网页文案写「reghdfe 和 avar」「读了 3 个公开源文件」。旁白里的「三个 Stata 程序」说的是这条命令依赖几个程序，不是智能体读了几个。

## 5 没有放进来的内容

- **题目数据的内容**。运行数据只保留步骤序号、起止时间、工具名、退出码和每条命令的第一行；画面上引用的终端输出是汇总数字，没有数据行。
- **其他模型和其他运行**。本题的评分脚本不调用模型，画面上也不出现裁判模型。
- **密钥**。工程里没有任何密钥。

## 6 相对 HR v3 引擎改了什么

完整差异见 `ENGINE-CHANGES.patch`（对 `video-demo/sources/hr/` 里 v3 源工程的 `engine/` 做的 diff）。默认值都没变，财务和 HR 的分镜不受影响。

- **写死的文字改为从分镜读取**：页眉的赛道名、工具循环标题、左栏标题和脚注、台账图例、输出目录和文件类型、容器和输入的说明、交接画面的文字、片头的评分方名称、片尾的出处。
- **分镜可以自带画面和提示点**：`story/econ_scenes.py` 提供七个画面（问题、两列设定、队列权重、协变量组合表、逐数比对、p 值的分布、边界）；`story/econ.py` 的 `GUIDE` 提供提示点。
- **Terminus-2 的工具调用**：它只有一个往终端里打字的工具，台账和全程图改为按调用的实际作用上色。
- **引导角色**：`robot/sprite.html` 按参数选择武器；这把武器的枪口位置更高，仰角超过约 83 度时枪口会落进机身框，所以加了仰角上限（`robot_max_aim=80`），超过时把站位向左移。
- **字标**：改为「Global Metacase Challenge」，页眉里相应缩小。
- **题目卡片**：列数和顶部标签宽度可由分镜指定，卡片可以不带序号。

## 8 重新渲染

需要 Python 3.12、FFmpeg。在本目录下：

```bash
python -m venv .venv
.venv/bin/python -m pip install -r requirements-render.txt
.venv/bin/python -X utf8 engine/render.py econ --workers 2
.venv/bin/python -X utf8 tools/screen_text.py econ
.venv/bin/python -X utf8 tools/laser_text.py econ
.venv/bin/python -X utf8 engine/package_econ.py
```

- 直接使用 `build/econ/voice/` 里缓存的 28 段旁白和 `build/econ/voice.json`。只有改了旁白才需要运行 `engine/voice.py econ`（要装 `edge-tts`，需联网）。
- 这次是在 macOS 上渲染的：等宽字体用系统的 SF Mono，符号用系统字体；实际用到的字体记录在 `font-selection.json`。
- 重新生成运行数据：`python tools/build_econ_data.py <该次运行的 replay 目录>`。
- 重新生成机器人素材：把网站工作副本和本工程放到同一个本地静态服务下（分别挂在 `/site/` 和 `/work/`），然后 `node robot/render_sprites.mjs --base http://127.0.0.1:<端口> --out robot/sprites-terminus --angles -90:90:1 --size 400 --weapon blaster-m.glb`。需要 Node、`playwright-core` 和 Chrome。
- `tools/` 里 `patch_engine*.py`、`patch_robot.py`、`revise*.py` 是制作过程中一次性执行过的修改脚本，已经生效，不要再运行。

## 9 内容边界

- 这是对一次已有试跑的编辑回放，没有重新运行智能体，也没有重新评分。
- 评分是一次试跑的评分脚本结论，不是准确率，也不是排名。
- 智能体是照公开源码重写了一个已发表的估计方法，视频没有说它独立推导了方法。
- 智能体报告的基准设定没有同作者的脚本核对过，它自己的脚本里也写了这一点。
